# hrva.cc — URL Shortener Frontend

Next.js 16 App Router + React 19, deployed on Cloudflare Workers via `@opennextjs/cloudflare`. Deployed at [hrva.cc](https://hrva.cc).

---

## Commands

| Command | Purpose |
|---------|---------|
| `npm run dev` | Next.js dev server (TurboPack) |
| `npm run build` | Standard Next.js build |
| `npm run build:cf` | Cloudflare Worker build |
| `npm run preview` | Build + Cloudflare local preview |
| `npm run deploy` | Build + Cloudflare deploy |
| `npm run cf-typegen` | Regenerate `cloudflare-env.d.ts` from wrangler config |
| `npm run lint` | ESLint (`eslint .`) |
| `npm run check:utm` | Node assertions for `lib/utm.ts` (`scripts/check-utm.mjs`), prints `ok` |

`npm run dev` proxies `/api/v1`, `/oauth2`, `/login` and `/api/changelog` to `http://localhost:8080`, and dev short links (`getShortBaseUrl()`) use the same origin. Set `DEV_API_ORIGIN` when starting the dev server to target another backend, e.g. `DEV_API_ORIGIN=http://localhost:18080 npm run dev`; it's read once at startup (`next.config.mjs`), so restart to change it.

No test framework is set up.

`npm run lint` exits 1 on this branch: the baseline is **21 errors and 4 warnings**. A change passes lint when the totals don't rise and no file it touches has a problem. Count them with `npx eslint . -f json | jq '{errors: ([.[].errorCount] | add), warnings: ([.[].warningCount] | add)}'`.

## Architecture

### Routing (`app/`)
- `/` — Landing page (public URL shorten + logged-in experience)
- `/register`, `/reset-password/[token]` — Auth flows
- `/login` — Email and password, **Sign in with a passkey** (`components/auth/passkey-sign-in-button.tsx`, with a **How passkeys work** link under it) and passkey autofill from the Email field (`usePasskeyAutofill`: only while the tab is visible, it runs again when the tab comes back, and never again after a sign-in succeeds). A two-step account gets the shared `SecondStep` screen (`components/auth/second-step.tsx`) with the methods from the login response: **Use a passkey or security key** for `WEBAUTHN`, then **or enter a code** and the code field for `TOTP` / `RECOVERY_CODE` (trimmed before sending; the backend ignores case, spaces and a missing dash). Under it, **Use a different account** returns to the password form with the email kept (password cleared) and **Lost your passkey or codes?** opens `/help/passkeys#lost-device` in a new tab. A 410 returns to the form with the backend's text as the toast (expired, or out of tries), except an expired passkey request from the verify call (`This request expired. Try again.`): that stays on the step, shown under the passkey button, and the next press fetches fresh options. 401, 403 and 400 texts (tries left, account and network locks) are shown as the backend sends them; the browser-side wrong-key text is only for `NotAllowedError`. `?next=` (checked by `safeNext`) is where a sign-in lands; the Google button keeps it in `sessionStorage` (`post-login-next`) for the callback
- `/auth/callback` — Where Google and GitHub sign-ins come back: `?token=` signs in; `?pendingToken=…&methods=TOTP,WEBAUTHN,RECOVERY_CODE` shows `SecondStep` and removes both from the address bar (`replaceState` in a layout effect; an empty `methods` means none). Its way out is **Back to sign in** (`/login`): a button when there's no code field, a link under the form otherwise. A 410 shows the backend's text on the error card; `?error=` (`no_email`, `account_inactive`, `two_step_unavailable`, `invalid_email`) shows its message, any other code "Authentication failed."
- `/validate/[short]` — Peek at a URL before visiting
- `/fortune`, `/egg` — Easter eggs
- `/changelog` — Release notes (fetches from backend `/api/changelog`)
- `/help` — Help index, a plain `guides` list in `app/help/page.tsx` with one entry per guide (add a guide there). `/help/utm` — Campaign tracking (UTM) guide. `/help/passkeys` — the passkeys and security keys guide (`prose-custom`, anchors `#what-passkeys-are`, `#add-a-passkey`, `#sign-in`, `#two-step`, `#recovery-codes`, `#lost-device`, `#privacy`; Settings links to it and to `#two-step`). `/help/stats` — "hrva.cc in numbers": what the public numbers mean (`#numbers`, linked from `/stats`) and QR scans against other clicks (`#qr-scans`, linked from the analytics note and the landing QR card), plus `#privacy`; the index lists it twice, once per section, and its "QR codes downloaded before …" date is `QR_SCANS_START`, formatted at build time. All four are static server pages like `/privacy` and `/terms`, in `app/sitemap.ts`, and the footer's **More** column links to `/help`
- `/help/link-in-bio` — the bio pages guide, a static server page like the other guides (`prose-custom`, anchors `#what-a-bio-page-is`, `#create`, `#add-buttons`, `#arrange`, `#look`, `#share`, `#views`, `#missing-buttons`, `#handle`, `#search-engines`, `#report`, `#privacy`), in `app/sitemap.ts` and the `guides` list; the editor's **How bio pages work** links to it
- `/stats` — "hrva.cc in numbers", the public site-wide numbers: a static server page (`SiteHeader`, `SiteFooter`, no data fetching) around the client `PublicStats` (`components/public-stats.tsx`), which loads `GET /public/stats` in the browser through `usePublicStats()`. The lead says most numbers cover the last 30 full days. In order: the date line (`from` – `to`, then "Updated" as a relative time), Active links, Links created and Clicks, a 30-day `ClicksChart` without the visitors line ("No clicks in the last 30 days." over it when the 30-day clicks are 0), Keeping links safe (Harmful links blocked: the last 30 days, with the all-time count in its hint; Visitor reports handled; Average review time as `formatDuration` ("1 h 36 min", spoken "1 hour 36 minutes" in an sr-only span) or "No reviews in the last 30 days"), Blocklists in use (name wrapped, Blocks links / Flags links for a person to check, domains; empty: "No blocklists are loaded right now."), and links to the phishing blog post, `/help/stats#numbers` and `/privacy`. Nothing on it is about a single link or person. The error state reads "Couldn't load the numbers." (`role="alert"`). A 429 adds the backend's text and has no Try again button, like `AnalyticsError` with a refusal. Otherwise Try again calls `refetch()`: the box and the focus stay on the button while it runs (`aria-disabled`, an sr-only status "Trying again"). Focus never drops to `body` when the box changes: if the visitor started the retry, or the box held focus when it changed (an automatic refetch on window focus included), focus moves to the date line once the numbers arrive, or to the alert text (`tabIndex={-1}`) when Try again disappears because of a 429. The box and the button report losing focus from a layout-effect cleanup, which runs before React removes their DOM, and focus moves only while `document.activeElement` is `body`, so it is never taken from somewhere else. Once numbers are loaded, a failed background refetch keeps them. The backend answers with `Cache-Control: public, max-age=600`, so a browser that loaded the numbers in the last 10 minutes doesn't ask again (use a fresh profile when checking locally). The footer's **Product** column links to it after Changelog, and it is in `app/sitemap.ts`
- `/unavailable?s=&reason=` — Where the backend sends a short link that can't redirect (`noindex`). `reason` is `blocked`, `expired`, `limit`, `inactive` or `missing`; anything else falls back to the `missing` line. "Report a link" carries `s` to `/report`
- `/report?s=` — Public report form: short link (prefilled from `s`), category, details. The link is reduced to its bare code (`hrva.cc/abc` → `abc`, host taken from `getShortBaseUrl()`) before `reportApi.report()`; a 429 shows the backend's text
- `/report` also takes a bio page (`toReportTarget` in `app/report/page.tsx`): `@name`, `hrva.cc/@name` and `app.hrva.cc/bio/name` (any scheme, `www.`, query or fragment) send `shortUrl: "@name"`; a short code is 1–32 characters of `[a-zA-Z0-9_-]`, as in the backend. A prefilled bio page (`?s=%40name`, from **Report this page**) reads **Report a bio page** and asks which link on the page is wrong. An unreadable target, or the backend's 400 starting with `Enter a hrva.cc`, shows `Enter a hrva.cc short link or bio page, like hrva.cc/abc or hrva.cc/@name.` under the field (`flushSync`, then focus). Send is `aria-disabled` + `aria-busy` while sending, never `disabled`, so focus stays on it, and a `submitting` ref ignores a second Enter
- `/bio/[handle]` — Public bio page, see Bio pages below
- `/dashboard/*` — Protected; user's URLs, API keys, settings
  - `/dashboard` — My URLs. `New URL` (and the empty state's `Shorten a URL`) open the controlled `CreateUrlDialog`, which has no `DialogTrigger`, so its `onCloseAutoFocus` returns focus to the button that opened it, or to `New URL` once that button is gone
  - `/dashboard/settings` — Profile, password (email accounts only), `PasskeysCard`, `TwoStepCard`, connected apps, data export and account deletion
  - `/dashboard/bio` — The bio page editor, see Bio pages below
  - `/dashboard/analytics` — Analytics overview: the all-time counters (links, active, expired, all-time visits), then for the range the totals, the clicks vs daily unique visitors trend and the top 10 links by clicks, each opening its own view with the same range. `?link={id}` shows one link (its owner or an admin): summary, range totals, the clicks vs daily unique visitors chart, then **QR scans and other clicks** (`QrScansList`, first in the breakdown grid) and the referrer, country, device, browser and OS breakdowns. `?days=7|30|90|365` picks the range (default 30, left out of the URL); anything else falls back to 30, and a `link` that isn't a positive integer shows the overview. The dashboard row's and All URLs' "View stats" open it. A tagged destination adds a Campaign tags card (Source, Medium, Campaign, Term, Content) under the link summary. It reads the tags from the summary's `longUrl`, which the backend returns only to the link's owner or an admin, and stays hidden when the destination has no tags
  - `/dashboard/analytics?view=bio` — Bio page analytics (`components/analytics/bio-analytics.tsx`, `useBioAnalytics(days)`, key `["analytics", "bio", days]`): Views (each visitor once a day) and Bot views (hint "Link previews and crawlers. Not counted as views.") for the range, `BioViewsChart` (with an `sr-only` date → views list beside the `role="img"` chart) or "No views in this range yet.", and per button **From your bio page** (the link's clicks referred by hrva.cc's own host) and **All clicks**; a button that isn't shown says why from the response's `visible` and `linkState`: **Hidden**, else the link-state badge text (**Not on your page** only if a backend omits both). `AnalyticsViewSwitch` (Links / Bio page) switches between the views; a caller without a page gets a **Create your bio page** link
- `/admin/*` — Protected + `ROLE_ADMIN`
  - `/admin` — Users table. "Possible scammers only" sends `possibleScammer=true` (server-side filter); a Possible scammer badge comes from `user.possibleScammer`; Block / Unblock user each ask for confirmation and toast the number of links blocked or restored. Provider uses `providerLabels` ("Email and password"). Below the table's container threshold, ID, API key slots and last login move under the email and a Sort by select replaces the hidden sort headers
  - `/admin/dashboard` — Stats page: site-wide totals in five tabs with a range picker. `?tab=traffic|links|users|safety|system&days=7|30|90|365`; the defaults (`traffic`, 30) are left out of the URL (`adminStatsHref`), and an unknown value falls back to the default. Each tab loads on its own and draws its charts and links from the range in the response (`data.days`), so a range change keeps the old chart, axis included, until the new one arrives. Charts sum days into weeks at 90 days and months at 1 year (`bucketRows` in `lib/admin-stats.ts`) and mark today, which isn't over, as in progress:
    - Traffic: clicks, daily unique visitors and bot clicks with the daily chart, bot share, clicks on links with and without an account, all-time unique visitors, top 10 links, **QR scans and other clicks** (`QrScansList`, first in the breakdown grid), and the referrer, country, device, browser and OS breakdowns
    - Links: links created per day stacked by how they were made (`createdViaLabels`), created in range, right now (active, inactive, past expiry date, password, visit limit, expiry date), blocked links by reason, top tags, top destinations, newest 10 links
    - Users: sign-ups per day by sign-in method, accounts, sign-in methods, activity (last 7 / 30 days), API keys (active, expired and "Revoked or out of calls", which add up to every key, plus calls used), AI connector accounts and apps
    - Safety: reviews opened per day (checks vs visitor reports), open reviews, possible scammers, resolved in range and time to resolve, links blocked per day (the three most common reasons in the range as shades, the rest as "Other reasons"; the tooltip lists all six), domain rule counts, blocklist sources
    - System: app version and uptime, DB and Redis health, requests and 5xx, link cache hit ratio, JVM heap, Redis memory and key counts (`≥` when capped), database engine and size (a banner when short links aren't unique), emails per day, redirect timing, and the login rate limits panel (`LoginRateLimits`, the only IPs on the page)
  - `/admin/urls` — All URLs with bulk actions (checkbox multi-select). Search matches short link, destination and owner email (a pasted `hrva.cc/abc` is reduced to `abc`). `?search=<text>` opens the page with the box filled and the list filtered (`useAddressSearch`, inside a `Suspense` boundary with the five-row skeleton as fallback); the burst alert links here as `/admin/urls?search=<domain>`. Typing keeps the address in step with `history.replaceState`: `search` is set while the trimmed text isn't empty and removed otherwise, and `page`, `size`, `sort` and `order` stay. The box adopts the address only when the address itself changes and differs from what the page last wrote (`seen` and `written` state compared during render, no effect), so the sidebar's All URLs link clears it and Back/Forward follow it, while fast typing never gets an older value written back; filters Active/Deactivated, Expired only, Anonymous only; Owner sorts by `owner.email`; Unique visitors is the link's `visits` (unique visitors per link per day, added up). A Suspicious line shows the backend's `suspiciousReasons`, a Blocked status has its `blockReason` (`blockReasonLabels`) on a line under the badge, and the destination is shown in full (wrapped, no truncation) with an "Ends at" line when `finalUrl` differs; an In review badge (`reviewOpen`) links to `/admin/review?entry=<id>`; the globe button opens `BlockDomainDialog`. Long URL has its own column (at least 27rem) only from a 78.25rem container (the 1536 px window); below that it is a wrapped line under the short link. Owner and Created are columns from 57rem (the 1280 px window); below that they move under the short link too and a Sort by select replaces the hidden sort headers; below `@2xl` unique visitors and status follow. The edit dialog's labels are tied to their inputs through `useId`
  - `/admin/review` — Review queue of flagged links (`adminApi.getReviewQueue`), filterable by reason and age. Each row has two labelled buttons, Looks fine (`OK`) and Block link, and a More menu (`DropdownMenu`, `modal={false}`) with Trust domain, Block domain and Block user (disabled, with a note, on an anonymous link); all but Looks fine confirm first, in dialogs kept outside the menu. Created shows the relative age ("3 months ago") over the date and the flag time. `?entry=<urlId>` highlights and scrolls to that row, or says it's no longer open. Multi-select like All URLs (row checkboxes, a select-all for the page, cleared on a page, size or filter change): the bar shows "N selected", Looks fine, Block N links, Trust domain, Block domain, Block user and Clear, and sends one `adminApi.resolveReviews` call. All but Looks fine confirm with the number of links; Block N links says how many owners are emailed (anonymous links have none); Trust domain and Block domain also list the distinct domains from each entry's `host` / `registrableDomain` (the backend's defaults; entries without a domain, IPs included, are counted as staying open); Block user is disabled while an anonymous link is selected. The toast gives the resolved and failed counts (with the distinct backend errors), then the same query keys as a single resolve are invalidated. After a row action removes the row, focus moves to the next row's Looks fine; after Block domain, a bulk action or a row action that also removed that next row, it goes to the first row left once the refetch has rendered (when the page emptied, once the page before it has loaded), and to the heading only when none are left. While a row is busy its More menu doesn't open
  - `/admin/review` also has a **Bio pages** section (`components/admin/bio-page-review-section.tsx`, `id="bio-pages"`) above the **Links** heading, shown only while bio page reviews are open: @handle (new tab), name, owner, reasons, flag time, **Looks fine** and **Hide page** (the hide dialog, reason prefilled). `?bio={pageId}` highlights and scrolls to an entry or says it's no longer in the queue; `#bio-pages` (the decisions email's link) scrolls there, or says **No bio pages are waiting.** when the queue is empty. Cancel returns focus to the Hide page button, or to the first remaining row when it's gone
  - `/admin/blocklists` — Blocklist sources (enable switch, Refresh now, add/edit/delete), domain rules in Blocked / Trusted tabs (adding a Block rule toasts `Blocked N links on <domain>`, or `Blocked <domain>. No active links used it.` when it matched nothing), and a URL tester that shows the backend's verdict (`adminApi.checkUrl`)
  - `/admin/reserved` — Reserved aliases: a form (alias, trimmed before sending, at most 32 characters, and a reason with a character count up to 200) whose invalid or refused alias shows inline under the field, with focus back on Alias after a reserve; a searchable table of the custom reservations (added when and by whom, which links already use the alias, a confirmed remove that says when the alias frees up if links still use it, or "No custom reservations yet."); and the built-in words as one wrapped line under it (no remove)
  - `/admin/api-keys` — All API keys; below a 46rem container, owner and created move under the key
  - `/admin/health` — Health: database, Redis and SMTP, from the legacy `GET /admin/stats` (polled every 30 s) and the newest email-log entry. A failed load shows an error with Retry instead of "Disconnected"; a failed refresh keeps the last answer with a note. SMTP reads Checking until the email log answers. The footer names what's down ("Redis isn't connected. The database is.")
  - `/admin/audit-log` — Admin action audit trail. `action` is an `AuditAction` (string-literal union in `types.ts`) shown through an explicit label map ("Resolved review", "Blocked domain", "Revoked link", "Reserved alias", "Removed reserved alias", …; an unlisted value is title-cased) and a colour map; `failed` adds "(failed)" in red. The Action select filters on the server (`?action=`); times go through `parseServerDateTime()`. Target types read as words (`targetTypeLabels`: `Url` is "Link", `ReservedAlias` "Reserved alias"). Below a `@4xl` container, target type, target and details move under the action badge. A failed load has Retry
  - `/admin/email-log` — Email delivery log; failed emails the backend still has content for (`resendable`) get a Resend button. "Failed only" sends `status=FAILED` (`adminApi.getEmailLog(page, size, status?)`; the backend also takes `SENDING`, `SENT` and `RESENT`), goes back to the first page, and is kept in the address as `?status=FAILED` (read on load, written with `history.replaceState` next to `usePagination`'s params); with it on, the empty state reads "No failed emails." After a resend removes the row or its Resend button, focus moves to the next Resend, else to Failed only Below a 59rem container, subject, status and error move under the recipient (a recipient may break after `@`). A failed load has Retry
  - `/admin/bio-pages` — Bio pages (`components/admin/bio-pages/`, `useAdminBioPages`): search by handle, name or owner email (`?search=`, debounced, so the Discord link prefills it), **Hidden only** (`?hidden=true`), columns Page (@handle opening `/bio/{handle}` in a new tab, or No handle, and the name), Owner, Buttons (`{visible} of {total} shown`), Status (Live, Hidden: reason, No handle: reason or Owner deactivated, plus an In review badge linking `/admin/review?bio={id}`) and Created, and the actions Hide / Unhide, Change handle and Revoke handle (`BioPageReasonDialog` with the prefilled reason and four quick reasons, `BioPageHandleDialog`; revoke sends `expectedHandle`). A failed load or refetch shows the error with Retry, never stale rows. The Users stats tab adds a Bio pages grid (Pages, Hidden) and the Traffic tab Bio page views and Bio page bot views, each only when the backend sends them

### API Client (`lib/api-client.ts`)
- `request<T>(method, path, body?, headers?)` — fetch wrapper with auth token injection
- Reads `localStorage.getItem("auth-token")` and sends it as-is in the `Authorization` header. The stored value already starts with `Bearer ` (the login response's `token`; the OAuth callback adds the prefix)
- `ApiError` class exposes `.status` and `.message`; `REQUEST_FAILED` is the fallback message when a 4xx body has none. A network failure (`fetch` throws; status `0`) or a 5xx without a JSON message (the dev proxy, a Cloudflare error page) gives `CANT_REACH`, "Can't reach hrva.cc right now. Check your connection and try again."; a 5xx with `{ error }` (the Redis-down 503s) keeps its text
- `request()` reads JSON or plain-text bodies (`POST /auth/register` answers with the bare email); error messages come from `error`, `message`, or the joined field messages of a validation response
- Signing in or out clears the React Query cache; a failed `/users/me` only drops the token on 401/403
- API base URL switches by env:
  - **Dev**: `/api/v1`
  - **Prod**: `https://hrva.cc/api/v1`
- **`urlApi`** — URL CRUD (create, list, peek, preview, QR, update, deactivate, delete, bulk, export)
- **`userApi`** — User CRUD (me, list, update, password, delete); `list` takes `possibleScammer`
- **`adminApi`** — Admin operations (legacy stats for the Health page, export, audit log with an optional `action` filter, email log with an optional `status` filter, login attempts) and moderation:
  - stats page: `getTrafficStats(days)`, `getLinksStats(days)`, `getUsersStats(days)`, `getSafetyStats(days)`, `getSystemStats(days)` (`GET /admin/stats/{tab}?days=`; System uses `days` only for the emails chart)
  - reserved aliases: `getReservedAliases()`, `reserveAlias({ alias, reason })`, `unreserveAlias(id)` (`/admin/reserved-aliases`; a duplicate or built-in alias is a 409 whose message is toasted)
  - blocklist sources: `getBlocklistSources`, `createBlocklistSource`, `updateBlocklistSource`, `deleteBlocklistSource`, `refreshBlocklistSource` (`/admin/blocklist-sources`, `POST …/{id}/refresh`)
  - domain rules: `getDomainRules(type)`, `createDomainRule` (returns `{ rule, linksAffected }`), `deleteDomainRule` (`/admin/domain-rules`)
  - review queue: `getReviewQueue({ page, size, reason, olderThanDays })`, `resolveReview(urlId, action, domain?)` (`/admin/review-queue`, `POST …/{urlId}/resolve`), `resolveReviews(urlIds, action)` (`POST /admin/review-queue/resolve` with 1–100 distinct ids, returns `{ resolved: number[], failed: { urlId, error }[] }`)
  - users: `blockUser`, `unblockUser` (return `{ linksAffected }`), `getPossibleScammers` (user ids)
  - `checkUrl(url)` — `POST /admin/url-check`, the verdict (`ALLOWED` / `BLOCK` / `FLAG` / `CLEAN`) a new link would get
- **`analyticsApi`** — `getUrlAnalytics(id, days)` → `GET /analytics/urls/{id}?days=` (summary, totals, zero-filled `daily`, top-10 breakdowns plus `other`); `getOverview(days)` → `GET /analytics/overview?days=` (totals, zero-filled `daily`, top 10 links by clicks, all-time counters)
- **`reportApi`** — `report({ shortUrl, category, details? })` → `POST /reports` (public, rate-limited per network)
- **`publicApi`** — `getStats()` → `GET /public/stats` (public, no token needed, 60 an hour per network; a 429 carries the text the page shows), typed `PublicStatsResponse`
- **`bioApi`** — `mine`, `create(handle)`, `update(page)` (the whole page), `changeHandle(handle)`, `remove`, `availability(handle)`, `analytics(days)` (`/bio-pages/me`, `/bio-pages/handles/{handle}/availability`, `/analytics/bio-page`). **`adminBioApi`** — `list(filters, page, size)`, `hide`, `unhide`, `changeHandle`, `revokeHandle(id, reason, expectedHandle)`, `reviews(page, size)`, `resolveReview(pageId, action, reason?)` (`/admin/bio-pages`, `/admin/bio-page-reviews`). Both sit at the end of the file
- `ApiError.fields` holds a validation response's field messages (`{ "buttons[2].title": "…" }`) next to the joined `message`; empty for `{ error }` bodies. The bio editor maps them to per-button errors
- **`authApi`** sign-in methods: `login` answers with `twoStepRequired`, `pendingToken` and `methods` instead of a token when two-step verification is on; `secondStepTotp(pendingToken, code)`, `secondStepPasskeyOptions(pendingToken)`, `secondStepPasskey(pendingToken, ceremonyId, credential)` (`/auth/2fa/totp`, `/auth/2fa/webauthn/options`, `/auth/2fa/webauthn/verify`); `passkeyOptions()`, `passkeySignIn(ceremonyId, credential, rememberMe)` (`/auth/passkeys/options`, `/auth/passkeys/verify`); `setupTwoFactor`, `enableTwoFactor` (returns `[]` when unused recovery codes remain)
- **`passkeyApi`** — `list`, `registrationOptions(password?)`, `register(ceremonyId, credential, label)`, `rename(id, label)`, `remove(id, password?)` (`/users/me/passkeys`). Google and GitHub accounts send no password; the backend wants a sign-in from the last 15 minutes instead and answers 401 otherwise
- **`twoStepApi`** — `status` (`enabled`, `totp`, `passkeys`, `recoveryCodesRemaining`), `enable` (keys only; `[]` when unused codes remain), `disableOptions`, `disable({ code } | { ceremonyId, credential })`, `removeTotp(code)` (`/users/me/two-step`)
- Endpoints returning paginated data accept `UrlFilters` / `UserFilters` for search/status/date filtering

### Auth (`lib/auth-context.tsx`)
- React Context provider wrapping the tree under `Providers`
- On mount: reads `auth-token` from localStorage, calls `GET /users/me` to hydrate user
- `login()` returns a `LoginResult`: `{ status: "signed-in" }` (token stored, user set) or `{ status: "two-step", pendingToken, methods }`. `completeSignIn(signedIn)` stores the token and user for every other way in (passkey, second step, callback)
- `logout()` removes the token, clears the query cache and the user, and dismisses the `Sign in again` toast (`REAUTH_TOAST_ID`). `logoutTo(destination)` does the same and sends the dashboard and admin layouts (and `ProtectedRoute`) to `destination` instead of the sign-in page with `next` (account deletion → `/login`)
- Signed out on a dashboard or admin page (or inside `ProtectedRoute`) → `router.replace("/login?next=" + encodeURIComponent(pathname + search))`, so signing in returns to the same page, query included (a link to `/admin/urls?search=<domain>` opens with the search filled in), and Back doesn't loop. A signed-in non-admin on an admin page is still pushed to `/dashboard`
- `useReauthToast()`: a 401 for a Google or GitHub account shows one persistent `Sign in again` toast (id `REAUTH_TOAST_ID`) with the backend's text (passkey add and remove, account deletion); its action is `logout()`
- `isAdmin` derived from `user.authorities` containing `{ name: "ROLE_ADMIN" }`
- **No route protection middleware** — dashboard/admin layouts redirect client-side via `useEffect`
- `components/protected-route.tsx` (`ProtectedRoute`) has no importer: the dashboard and admin layouts do the same check themselves. It follows the same redirect rule so it stays safe if used again; remove it when convenient

### Data Fetching (TanStack React Query 5)
- Query client in `providers.tsx`: `staleTime: 30s`, `retry: 1`
- Hooks in `lib/hooks/` follow pattern: `useXxx()` for queries, `useXxx()` for mutations
- Mutations invalidate relevant query keys (`["urls"]`, `["apiKeys"]`, `["users"]`, `["me"]`); moderation keys live under `["admin", …]` (`["admin", "review"]`, `["admin", "domain-rules", type]`, `["admin", "blocklists"]`, `["admin", "reserved-aliases"]`)
- Stats page hooks (`hooks/useSiteStats.ts`): `useTrafficStats(days)` … `useSystemStats(days)`, keys `["admin", "stats", tab, days]`, with the previous range kept on screen while a new one loads and no retry on a 4xx. The legacy key `["admin", "stats"]` (`GET /admin/stats`, polled every 30 s) stays for the Health page
- `useUrlAnalytics(id, days)` — key `["analytics", "url", id, days]`; keeps the previous range on screen (dimmed) while a new range loads, and doesn't retry a 4xx
- `useAnalyticsOverview(days)` — key `["analytics", "overview", days]`; the same previous-range and no-4xx-retry behaviour
- `usePublicStats()` — key `["public", "stats"]`, `staleTime` 10 minutes, `retry: retryUnlessRefused` (a 4xx, the 429 included, is never retried; anything else once)
- `usePasskeys()` — key `["passkeys"]`; `useRenamePasskey()` / `useRemovePasskey()` invalidate `["passkeys"]` and `["twoStep"]`. `useTwoStepStatus()` — key `["twoStep"]`; `useRefreshTwoStep()` invalidates both and calls `refreshUser()`
- `useReviewCount()` — admin-only `GET /admin/review-queue?size=1` plus `GET /admin/bio-page-reviews?size=1`, the two `totalElements` summed through `Promise.allSettled` (one failing still shows the other; only both failing is an error), refetched every 60 s. Its key `["admin", "review", "count"]` sits under `["admin", "review"]`, so anything that resolves or blocks invalidates the count too
- Bio hooks: `useBioPage()` (key `BIO_PAGE_KEY`, `["bio", "me"]`; a 404 is `null`, "no page yet"), `useCreateBioPage`, `useSaveBioPage`, `useChangeBioHandle`, `useDeleteBioPage` (each cancels the read, then stores the answer), `useHandleAvailability(handle, enabled)` (debounced, key `["bio", "handle", …]`), `useBioAnalytics(days)`, and in `useAdminBioPages.ts` the admin list, the reviews and five mutations, which invalidate `["admin", "bio-pages"]`, `["admin", "review"]`, `BIO_PAGE_KEY` and `["admin", "stats"]` (an admin hiding their own page sees it in their editor at once). `useReorder({ items, onChange, label })` (`lib/hooks/useReorder.ts`) gives drag handles (pointer, with edge scrolling) and keyboard moves (↑, ↓, Home, End) with an assertive announcement, and keeps focus on the moved handle after the move commits
- Pagination via `hooks/usePagination.ts` — reads `page`, `size`, `sort`, `order` from URL search params
- Sortable columns: `SortHead` is a button inside the header cell (`aria-sort` on the cell), so a click, Enter or Space toggles asc/desc and resets to page 0; when the table reloads, focus returns to the header

### Response Shape Changes

- **List endpoints now paginated**: `GET /urls`, `/urls/all`, `/api-keys/all`, `/users` return `Page<T>` with `content`, `totalElements`, `totalPages`, `number`, `size`. Add `?page=0&size=20` query params.
- **`UrlResponse`** replaces raw `Url` entity — fields removed: `owner`, `apiKey`, `lastAccessed`, `lastSafeBrowsingCheck`, `platformType`, `threatEntryType`, `threatType`. New field: `ownerEmail` (populated for owned URLs, null for anonymous).
- **`ApiKeyResponse`** replaces raw `ApiKey` entity — fields removed: `owner`, `urls`
- **Error format**: now `{ "error": "message" }` instead of old `ApiException` wrapper
- **CORS**: now allows all standard methods (`GET, POST, PUT, PATCH, DELETE, OPTIONS`) instead of only `GET, POST`

## Gotchas

- **No `.env` files** — API base URL is hardcoded in `lib/utils.ts` and switches on `NODE_ENV`
- **Pointing dev at another backend**: set `DEV_API_ORIGIN` (default `http://localhost:8080`; see Commands), e.g. `DEV_API_ORIGIN=http://localhost:18082 npm run dev -- -p 3002`; it feeds the four rewrites in `next.config.mjs` and `getShortBaseUrl()` in `lib/utils.ts` (inlined through `env`), so never edit those to change ports. The backend's `app.frontend-url` decides where `/unavailable` and OAuth redirects go (3000 by default), so point it at the dev server's port
- **Auth token is stored with its `Bearer ` prefix** — `request()` adds nothing, so a token injected into `auth-token` by hand must include it
- **No middleware-based route protection** — dashboard/admin check auth in a client `useEffect`, creating a flash of unauthenticated content
- **`@/*` maps to root** — unlike the common Next.js pattern of mapping to `src/*`
- **Backend date-times are UTC with no offset** in production, where the container runs in UTC (`LocalDateTime`, e.g. `2026-10-24T09:15:00`); a backend run locally with `mvn spring-boot:run` sends the host's zone instead, so parsed times there show ahead by the host's offset (start the JVM with `-Duser.timezone=UTC` to match production). `new Date()` reads a string without an offset as local time, so it's off by the viewer's offset. Every admin screen parses them with `parseServerDateTime()` (`lib/analytics.ts`) before `formatDateTime()` / `formatTimeAgo()`, as do the analytics views and the dashboard's Created column; parse a nullable field behind a check (`value ? formatDateTime(parseServerDateTime(value)) : "—"`)
- **pnpm/npm**: lockfile is `package-lock.json` (npm), not pnpm
- **Changelog page** at `/changelog` is a client component — fetches changelog JSON from backend `/api/changelog`
- **Easter eggs**: Konami code (↑↑↓↓←→←→BA) on landing page, `/fortune`, `/egg`, console message hint
- **Animations**: `animate-copy-pulse` class, `CountUp` component for stat counters, staggered row entrance via `animate-fade-in` with inline delay, filter remount via `filterKey` 
- **Passkeys locally**: open the FE at `http://localhost:<port>`, never `127.0.0.1`, or the RP ID `localhost` (backend `application-local.yaml`) won't match. The backend's `app.passkeys.allowed-origins` must list that exact origin, e.g. `APP_PASSKEYS_ALLOWED_ORIGINS=http://localhost:3001` for a dev server on 3001
- **One WebAuthn request at a time**: a pending conditional (autofill) request must be aborted before another `navigator.credentials.get()` or `create()`. `getPasskey` and `createPasskey` abort the previous one; components abort their own on unmount
- **Help pages quote UI labels**: `/help/passkeys` names buttons, card titles, badges, their explanations and the email subject exactly (`Add a passkey or security key`, `Turn on with my passkeys`, `Use a passkey or security key`, `Copy codes`, `Download (.txt)`, `I've saved them`, `Use a different account`, `Lost your passkey or codes?`, …). `/help/stats` quotes the `/stats` labels (Active links, Links created, Clicks, Harmful links blocked, Visitor reports handled, Average review time, No reviews in the last 30 days, Blocklists in use, Blocks links, Flags links for a person to check) and the QR ones (URLs, Show QR code and View stats as the icons' screen-reader names, PNG, SVG, QR scans and other clicks). Change the page with the label
- **Every hrva.cc QR code carries the marker**: the three QR makers (`QrCustomizer`'s PNG canvas and SVG export, the signed-in home form's result, the create dialog) encode `withQrMarker(shortLink)`, so a scan opens `…/<alias>?qr` and counts as a QR scan; the backend drops `?qr` before redirecting. The shown link, its `href` and every copy button stay the plain short link. `QrCustomizer` (the dashboard's QR Code dialog) says under the code that its scans show as QR scans and that codes downloaded before `QR_SCANS_START` count as other clicks. The landing illustration (`https://hrva.cc`), the egg and the TOTP codes aren't short links and stay unmarked. A new QR code of a short link must use `withQrMarker`
- **Header and footer outside `Suspense`**: a page that reads `useSearchParams()` (`/report`, `/unavailable`) keeps `SiteHeader`, `SiteFooter` and everything that doesn't depend on the query outside its `Suspense` boundary, and the fallback is only the query-dependent part. A dynamic render streams the fallback and the resolved content into the same HTML, so a fallback holding the whole page sent two headers and two footers
- **Dev server over a production build**: `next dev` started on a `.next` left by `npm run build` reloads every page in a loop ("Compiled in 1ms"). Move `.next` aside first (`mv .next <somewhere>/next-prod-old`, never delete it), and run `npm run build` only after the dev server has stopped
- **Landing privacy figure** — The landing page's privacy figure quotes `UniqueVisitorCounter.visitorHash` and `AnalyticsDays.SALT_GRACE` by line number on GitHub; update the lines and the `#L` anchors when those files change
- **Bio pages quote labels too**: `/help/link-in-bio` names the editor's labels, badges and messages exactly (`Create page`, `Add from my links`, `Search your links`, `Drag, or use the arrow keys`, `Visible`, `Save changes`, `You have unsaved changes`, the five link-state badges, `Change handle`, `Choose handle`, `Allow search engines to index this page`, `Report this page`, `Delete bio page`, …). Change the page with the label
- **Share image fonts**: the OG route may only draw `ogSafeText` output, because `@vercel/og` fetches Google Fonts and emoji for any glyph its bundled Geist lacks. After a Next upgrade, re-run `fc-query` on `node_modules/next/dist/compiled/@vercel/og/Geist-Regular.ttf` and compare it with the ranges in `lib/bio.ts`
- **Brand icons are inline** (`components/bio/bio-icons.tsx`): Simple Icons paths (CC0) with `currentColor` and `aria-hidden`; LinkedIn, no longer in Simple Icons, is the letters `in` in a rounded square, and Website and Email are lucide's Globe and Mail. No icon package
- **Invisible characters**: `npm run check:bio` starts with `check:invisible`, which fails on zero-width, bidi and other invisible characters in `lib`, `app`, `components` and `scripts`. Build such characters from code points (`String.fromCodePoint`), never paste them
